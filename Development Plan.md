# book2audio: дизайн

Дата: 2026-08-29
Статус: черновик на согласование

## Задача

Локальный инструмент, который превращает PDF и EPUB в аудиокнигу. Всё считается на машине, без облака, без платных API, без аккаунтов.

Вход: файл книги, язык (ru или en), диапазон страниц.
Выход: m4b с главами. Опция: mp3 по главам.

Интернет нужен один раз, чтобы скачать модели голосов. Дальше работает оффлайн.

## Ограничения

- Хост: macOS 26, Apple Silicon. На машину ставится только Docker Desktop
- Всё исполнение внутри контейнеров: Python, ffmpeg, модели, зависимости
- Образ собирается под `linux/arm64`. Эмуляция amd64 через Rosetta замедляет синтез в 5-10 раз и недопустима
- MPS внутри Docker на macOS недоступен, ускорения от GPU не будет. Silero и Piper рассчитаны на CPU, так что это приемлемо
- Один пользователь, одна задача за раз
- Русский и английский. Другие языки за рамками

## Выбор движков синтеза

| | Русский | Английский |
|---|---|---|
| Движок | Silero TTS v4 | Piper |
| Голоса | baya, kseniya, xenia, aidar, eugene | lessac, amy, alan |
| Формат модели | PyTorch, `ru_v4` | ONNX, файл ~60 МБ |
| Частота | 24 или 48 кГц | 22.05 кГц |
| Скорость на CPU | быстрее реального времени в разы | быстрее реального времени в разы |
| Лицензия | открытая, дикторы студийные | MIT, дикторы студийные |

Голоса синтезированы из лицензированных студийных записей. Клонирования живых людей нет.

Книга на 12 часов звучания синтезируется примерно за час. Точное число зависит от голоса и частоты дискретизации, замерим на первой книге.

## Архитектура

Конвейер из 7 стадий. Каждая стадия читает результат предыдущей и ничего не знает про остальные.

```
загрузка → извлечение → чистка → сегментация → синтез → сборка → выдача
```

Ядро конвейера пишется как библиотека и CLI. Веб-UI это тонкая обёртка сверху. Так конвейер тестируется без браузера, и его можно гонять пачками из скрипта.

### Дерево модулей

```
book2audio/

    models.py          # Document, Chapter, Block, Job
    pipeline.py        # оркестрация стадий, события прогресса
  extract/

    pdf.py             # PyMuPDF
    epub.py            # ebooklib + BeautifulSoup
  clean/
    layout.py          # колонки, порядок блоков
    boilerplate.py     # колонтитулы, номера страниц
    footnotes.py       # сноски по размеру шрифта
    text.py            # переносы, склейка строк, кавычки
    speech.py          # числа, аббревиатуры, римские цифры
  segment/
    chunker.py         # предложения → чанки, паузы
  tts/
    base.py            # протокол TTSEngine
    silero.py
    piper.py
    cache.py           # sha256 → wav
  assemble/
    audio.py           # ffmpeg concat, m4b, метаданные глав
  web/

    static/            # index.html, app.js, style.css
  cli.py               # typer
```

### Главные интерфейсы

Два протокола держат всю систему. Всё выше по потоку выдаёт текст, всё ниже потребляет wav.

```python
class Extractor(Protocol):
    def extract(self, path: Path, page_range: tuple[int, int] | None) -> Document: ...


class TTSEngine(Protocol):
    sample_rate: int

    def synth(self, text: str, out_path: Path) -> None: ...
```

Замена Silero на другой движок трогает один файл.

## Стадии

### 1. Загрузка

Файл кладётся в рабочую папку задачи `work/<job_id>/`. Тип определяется по сигнатуре, не по расширению.

### 2. Извлечение

**PDF, через PyMuPDF.** Берём `page.get_text("dict")`, а не голый текст. Словарь даёт для каждого спана координаты, размер шрифта и начертание. Эти данные нужны на стадии чистки, поэтому терять их нельзя.

Диапазон страниц применяется здесь: страницы вне диапазона не читаются вообще.

Главы ищем по закладкам PDF (`doc.get_toc()`). Если оглавления нет, главой считается блок, у которого размер шрифта заметно выше медианного по документу.

**EPUB, через ebooklib.** Читаем spine, каждый документ разбираем BeautifulSoup, берём `h1`-`h3` как заголовки и `p` как абзацы.

Страниц в EPUB нет. Там spine и главы. Поэтому UI при загрузке EPUB подменяет поле «страницы» на список глав с чекбоксами. Притворяться, что страницы есть, смысла нет: у разных читалок разбивка разная.

### 3. Чистка (полный автомат)

Здесь живёт качество результата и сюда уходит основное время разработки.

Опорная величина для всех эвристик: **медианный размер шрифта основного текста**. Считается один раз по всему документу.

1. **Порядок блоков и колонки.** Смотрим x-координаты блоков. Если они собираются в 2 кластера, сортируем по (колонка, y). Иначе по y. Без этого двухколоночная вёрстка читается чересполосицей.

2. **Колонтитулы.** Собираем первые 2 и последние 2 строки каждой страницы, нормализуем (убираем цифры и пробелы). Строка, чья нормализованная форма встречается больше чем на 30% страниц, признаётся служебной и выбрасывается.

3. **Номера страниц.** Строки вида `^\s*[\divxlcIVXLC]+\s*$` в верхних или нижних 10% страницы.

4. **Маркеры сносок.** Спан из одних цифр, размер шрифта которого ниже медианного, выбрасывается. Обычным извлечением текста такое не отловить, поэтому пункт 2 стадии извлечения обязателен.

5. **Блоки сносок.** Блок с размером шрифта ниже медианного, стоящий в нижних 20% страницы.

6. **Не-проза.** Таблицы, подписи к рисункам, листинги кода. Признаки: моноширинный шрифт, много коротких строк подряд, много цифр на символ. Читать таблицу вслух бесполезно, выбрасываем.

7. **Переносы.** `(\p{L}+)-\n(\p{Ll}+)` склеиваем в одно слово. Проверка по словарю через `pymorphy3` для русского, для английского по списку.

8. **Склейка строк в абзац.** Строка, не заканчивающаяся на `.!?…»"`, приклеивается к следующей.

9. **Нормализация под речь.** Числа прописью (`num2words`, поддерживает ru и en), римские цифры в заголовках глав, распространённые сокращения (`т.е.`, `стр.`, `см.`, `e.g.`, `Fig.`), URL и почта заменяются на «ссылка» или выбрасываются.

Эвристики срабатывают не на каждой книге. Отчёт по чистке (сколько блоков выброшено и по какому правилу) пишется в `work/<job_id>/clean_report.json`, чтобы было куда смотреть, когда результат разочарует.

### 4. Сегментация

Разбиваем на предложения через `pysbd` (умеет ru и en). Пакуем предложения в чанки до 800 символов, границу предложения не рвём. Если одно предложение длиннее лимита, режем по `;`, затем по `,`.

Паузы задают ощущение аудиокниги:

| Граница | Пауза |
|---|---|
| Между чанками внутри абзаца | 250 мс |
| Между абзацами | 700 мс |
| Между главами | 1500 мс |

### 5. Синтез

Чанки идут по очереди через движок выбранного языка.

Кэш: `cache/<sha256(text + voice + rate + engine_version)>.wav`. Прогон на 12 часов падать будет, и без кэша каждое падение стоит часа работы заново.

Ошибка синтеза чанка: 2 повтора, потом на его место вставляется тишина, а сам чанк пишется в отчёт. Книга досчитывается до конца, а не умирает на 400-й странице из-за одной строки.

Промежуточные wav занимают много места. 24 кГц, 16 бит, моно это примерно 173 МБ на час, то есть около 2 ГБ на книгу. Перед стартом проверяем свободное место и отказываемся стартовать, если его мало.

### 6. Сборка

1. Конкатенация wav внутри главы через `concat` demuxer ffmpeg, паузы вставляются как файлы тишины
2. Файл метаданных `;FFMETADATA1` с блоками `[CHAPTER]`
3. Кодирование в AAC 64 кбит/с моно. Для речи этого достаточно, книга на 12 часов весит около 350 МБ
4. Обложка из PDF (первая страница) или из EPUB, если есть

Опция mp3 по главам: тот же конвейер, на последнем шаге пишется папка с пронумерованными файлами и тегами ID3.

### 7. Выдача

Ссылка на скачивание. Рабочая папка чистится по кнопке или через сутки.

## Веб-слой

**Бэкенд: FastAPI.** Один пользователь на localhost, поэтому Redis и Celery не нужны. Задачи держатся в SQLite в режиме WAL, синтез идёт в отдельном контейнере-воркере, который опрашивает таблицу задач раз в секунду. Одна задача за раз, остальные в очереди.

Воркер вынесен из веб-процесса ради одного свойства: прогон длится час, и веб-слой можно перезапустить или уронить, не убив задачу. Брокер для этого не нужен, хватает таблицы со статусом и `SELECT ... LIMIT 1` под транзакцией.

**Прогресс: SSE.** Поток в одну сторону, WebSocket тут избыточен. Событие:

```json
{"stage": "synth", "done": 412, "total": 3180, "eta_sec": 2140}
```

ETA считается по скользящему среднему последних 20 чанков.

**Фронтенд: одна страница, ванильный JS.** Сборщика нет, фреймворка нет. Экранов три:

1. Загрузка: drag-and-drop, выбор языка, диапазон страниц (или список глав для EPUB), выбор голоса с кнопкой прослушать образец
2. Прогресс: стадия, полоса, ETA, лог, кнопка отмены
3. Готово: плеер, скачивание, отчёт по чистке

Состояние задачи живёт на сервере, поэтому закрытая вкладка ничего не ломает.

## Окружение

Два сервиса из одного образа, различаются командой запуска. Пересборка стоит одну сборку, а не две.

```yaml
services:
  web:
    build: .
    platform: linux/arm64
    command: uvicorn book2audio.web.main:app --host 0.0.0.0 --port 8000
    ports: ["8000:8000"]
    volumes:
      - ./output:/data/output
      - models:/models
      - work:/data/work
      - db:/data/db
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request;urllib.request.urlopen('http://localhost:8000/health')"]
      interval: 30s

  worker:
    build: .
    platform: linux/arm64
    command: python -m book2audio.worker
    volumes:
      - ./output:/data/output
      - models:/models
      - work:/data/work
      - db:/data/db
    depends_on: [web]

volumes:
  models:
  work:
  db:
```

### Тома и почему именно так

| Том | Тип | Содержимое | Причина |
|---|---|---|---|
| `./output` | bind | Готовые m4b и mp3 | Единственное, что нужно на хосте |
| `models` | named | Веса Silero и Piper | Качаются один раз, переживают пересборку образа |
| `work` | named | Промежуточные wav, кэш чанков | Тысячи мелких файлов и 2 ГБ на книгу |
| `db` | named | SQLite с задачами | Общий для веб и воркера |

Промежуточные wav держатся в именованном томе намеренно. Bind mount на macOS идёт через VirtioFS, и запись тысяч мелких файлов туда заметно медленнее записи в том Docker. На хост уходит только финальный файл.

### Dockerfile

Многостадийная сборка на `python:3.12-slim-bookworm`.

Стадия `builder` ставит зависимости в venv. Стадия `runtime` копирует готовый venv и добавляет из apt только `ffmpeg` и `ca-certificates`. Компиляторы и заголовки в финальный образ не попадают.

Порядок слоёв: сначала `COPY requirements.txt` и установка, потом `COPY` кода. Правка кода не переустанавливает torch.

Torch ставится с индекса `download.pytorch.org/whl/cpu`. Иначе на linux/amd64 подтянутся пакеты NVIDIA и образ вырастет на пару гигабайт. Для arm64 колёса и так CPU-only, но индекс фиксируем ради предсказуемости.

Процесс работает под непривилегированным пользователем `app` с фиксированным UID. Права на тома выставляются в entrypoint.

Ожидаемый размер образа: около 2.5 ГБ, из них примерно 900 МБ приходится на torch.

### Первый запуск

```bash
docker compose up --build
```

Сборка занимает 5-10 минут. При первом старте воркер скачивает веса моделей в том `models`, это ещё около 200 МБ и пара минут. Прогресс виден в логах. Дальше сеть не нужна, тома переживают перезапуск и пересборку.

Интерфейс на `http://localhost:8000`.

### Разработка

Отдельный `compose.dev.yaml` подкладывает исходники томом и запускает `uvicorn --reload`. Правка кода не требует пересборки образа.

### Ресурсы

Синтез упирается в CPU. Docker Desktop по умолчанию отдаёт контейнерам меньше ядер, чем есть на машине. Если выделено 2 ядра вместо 8, книга считается вчетверо дольше. Проверяется в настройках Docker Desktop, раздел Resources. README должен про это говорить прямо, иначе первый прогон разочарует без понятной причины.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| PDF без текстового слоя | Определяем на извлечении по числу символов на страницу. Останавливаемся, объясняем, что нужен OCR |
| Модель не скачана | Качаем при первом запуске с прогрессом. Без сети пишем, что делать |
| Нет ffmpeg | Проверка на старте приложения, показываем команду `brew install ffmpeg` |
| Мало места на диске | Проверка перед стартом синтеза с оценкой размера |
| Чанк не синтезировался | 2 повтора, потом тишина и запись в отчёт |
| Смешанные языки в книге | Читается голосом выбранного языка. Известное ограничение, в UI предупреждение |

## Тестирование

- **Юнит, чистка.** Фикстуры из реальных страниц с известными колонтитулами и сносками. Каждая эвристика проверяется отдельно
- **Юнит, чанкер.** Лимит не превышается, предложение не рвётся, паузы расставлены по правилам
- **Интеграция.** PDF на 3 страницы до m4b целиком: проверяем длительность и число глав
- **Фейковый TTS.** В тестах движок подменяется заглушкой, которая пишет тишину длиной пропорционально тексту. Набор гоняется за секунды

## Порядок сборки

Каждая фаза заканчивается работающим состоянием.

1. **CLI-скелет.** PDF → текст → чанки → Silero → один wav. Сквозной прогон на одной книге. Дальше всё улучшает уже работающую цепочку
2. **Чистка.** Эвристики и фикстуры. Самая долгая фаза
3. **EPUB, Piper, m4b, кэш.** Полная функциональность в CLI
4. **Веб-бэкенд.** FastAPI, задачи, SSE поверх готового конвейера
5. **Фронтенд.** Три экрана, обработка ошибок, README
